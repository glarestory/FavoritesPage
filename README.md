# My Start Page

Chrome의 새 탭 페이지에서 영감을 받은 개인용 즐겨찾기 대시보드입니다. 검색, 카테고리별 즐겨찾기 관리, 테마·배경 설정, JSON 백업/복원을 기본적으로 브라우저에서 처리합니다. 선택적으로 계정을 만들면 즐겨찾기와 설정을 여러 기기에서 동기화할 수 있습니다.

## 주요 기능

### 검색
- 화면 중앙의 검색창에서 Enter로 바로 검색합니다.
- Google(기본), Bing, DuckDuckGo, Naver를 설정에서 선택할 수 있습니다.
- 앞뒤 공백을 제거하고 검색어를 URL 인코딩합니다. 빈 검색어는 이동하지 않습니다.
- `Ctrl+K`(macOS는 `Cmd+K`)로 검색창에 즉시 포커스합니다.
- 즐겨찾기 카드는 항상 새 탭에서 열립니다.
- 검색 결과를 새 탭에서 열지 설정할 수 있습니다.

### 즐겨찾기
- 기본 즐겨찾기 8개: Google, YouTube, GitHub, ChatGPT, Claude, Naver, Gmail, Google Drive
- 데스크톱에서 한 줄 8개를 기본으로 하며 화면 폭에 따라 6·4·3·2개로 반응형 조정됩니다.
- 추가·수정 모달에서 이름, URL, 카테고리, 선택적 아이콘 URL을 입력할 수 있습니다.
- URL에 스킴이 없으면 `https://`를 자동으로 붙이고, `http`/`https` 주소만 허용합니다.
- 중복 URL(끝 슬래시·해시 무시)을 차단합니다.
- 아이콘은 사용자 지정 URL → Google S2 favicon → 사이트 `/favicon.ico` 순으로 시도하고, 모두 실패하면 이름 첫 글자 아바타를 표시합니다.
- 긴 이름은 말줄임 처리됩니다.
- 카드 메뉴에서 수정, 삭제, 카테고리 이동, 왼쪽/오른쪽 이동이 가능합니다.
- 데스크톱에서는 카드를 드래그해 순서를 바꿀 수 있고, `순서 변경` 모드에서 이동 버튼을 사용할 수도 있습니다.
- 삭제 전 확인 대화상자를 표시합니다.
- 이름 또는 URL로 즐겨찾기를 필터링할 수 있습니다. 카테고리를 선택한 상태에서는 해당 카테고리 안에서만 필터링됩니다.

### 카테고리
- 기본 카테고리 6개: 개발, AI, 업무, 뉴스, 쇼핑, 기타
- 상단 카테고리 탭에서 전체 또는 특정 카테고리의 즐겨찾기만 볼 수 있습니다.
- `관리` 버튼에서 카테고리를 추가·이름 변경·삭제하고, 위/아래 버튼으로 탭 순서를 바꿀 수 있습니다.
- 카테고리 이름은 최대 20자이며 대소문자 구분 없이 중복될 수 없습니다. `전체`는 기본 탭 이름이라 사용할 수 없습니다.
- 카테고리는 최대 30개까지 만들 수 있고, 최소 1개는 남아 있어야 합니다.
- 카테고리를 삭제하면 해당 즐겨찾기는 `기타`로 이동합니다. `기타`가 없으면 첫 번째 남은 카테고리로 이동합니다.
- 카드의 `⋯` 메뉴 또는 수정 모달에서 즐겨찾리의 카테고리를 바꿀 수 있습니다.
- 카테고리와 표시 순서는 `localStorage`에 자동 저장됩니다.
- 기존 즐겨찾기에 카테고리 정보가 없으면 URL 도메인을 기준으로 개발·AI·업무·뉴스·쇼핑을 추론하고, 해당하지 않으면 `기타`로 분류합니다.

### 테마와 배경
- 라이트 테마가 기본이며 다크 테마로 전환할 수 있습니다.
- 배경 유형: 기본, 단색, 그라데이션, 이미지
- 단색: 8개 프리셋 + 사용자 지정 색상
- 그라데이션: 6개 프리셋
- 이미지: 접근 가능한 이미지 URL을 미리 확인한 뒤 적용, 어둡기(오버레이) 조절, 제거 가능
- 배경 밝기에 따라 텍스트와 헤더 색상을 자동으로 보정합니다.

### 데이터 관리
- 즐겨찾기, 카테고리와 설정을 `localStorage`에 자동 저장합니다.
- JSON 파일로 내보내기/가져오기할 수 있습니다. 현재 백업 형식은 버전 2입니다.
- 가져오기 전에 파일을 검증하고 미리보기를 보여준 뒤 확인을 받습니다.
- 잘못된 JSON, 누락된 필드, 중복 URL, 알 수 없는 카테고리, 지원하지 않는 테마/검색 엔진 등의 오류를 한국어 메시지로 안내합니다.
- 버전 1 백업처럼 카테고리 정보가 없는 파일도 가져올 수 있습니다. 이 경우 기존 카테고리를 유지하고, 가져온 즐겨찾기는 URL 추론 또는 `기타`로 분류합니다.
- Chrome에서 내보낸 북마크 HTML 파일을 가져올 수 있습니다. 브라우저 보안 정책상 Chrome 내부 북마크를 직접 읽지 않고, 사용자가 선택한 HTML 파일만 사용합니다.
- 북마크 폴더 이름을 카테고리로 변환할지 선택할 수 있습니다. 기존 카테고리와 이름이 같으면 재사용하고, 새 카테고리는 최대 30개 한도 안에서 추가합니다.
- 북마크 URL은 `http`/`https`만 허용하고, 제목이 없으면 도메인으로 대체하며 60자를 넘으면 줄입니다. 잘못된 URL과 건너뛴 이유는 미리보기에서 확인할 수 있습니다.
- 가져오기 전에 폴더별 항목을 미리 보고 체크박스로 선택할 수 있습니다. 기존 URL과 중복되면 `기존 즐겨찾기 유지` 또는 `가져온 항목으로 업데이트`를 선택하며, 파일 안 중복은 먼저 선택한 항목을 유지합니다.
- 북마크 가져오기는 기존 데이터를 대체하지 않고 병합합니다. 설정과 기존 즐겨찾기·카테고리는 유지되며, 최대 300개 즐겨찾기 한도를 넘는 가져오기는 거부합니다.
- 모든 데이터를 기본 상태로 초기화할 수 있습니다.
- 저장 데이터가 손상된 경우 기본값으로 복구하고 토스트로 알립니다.

### 계정 및 동기화(선택)
- 이메일과 비밀번호로 회원가입·로그인할 수 있습니다. 계정을 만들지 않아도 기존처럼 로컬 전용으로 사용할 수 있습니다.
- 로그인하면 현재 `localStorage` 데이터를 서버에 처음 업로드하고, 이후 변경 사항을 자동으로 동기화합니다.
- 다른 기기에서 로그인하면 서버에 저장된 즐겨찾기·카테고리·설정을 내려받습니다.
- 로컬과 서버가 모두 바뀐 경우 덮어쓰지 않고 충돌 카드를 표시합니다. `서버 데이터 사용` 또는 `로컬 데이터로 덮어쓰기`를 직접 선택할 수 있습니다.
- 낙관적 동시성(`baseVersion`)을 사용해 다른 기기의 최신 변경을 감지합니다. 오래된 버전으로 저장하면 `409`와 함께 현재 서버 스냅샷을 돌려줍니다.
- 네트워크 오류 시 로컬 데이터는 그대로 유지되고, 설정 화면에서 `다시 시도`할 수 있습니다. 브라우저가 온라인으로 돌아오면 자동으로 다시 시도합니다.
- 로그아웃해도 로컬 데이터는 삭제되지 않습니다. 서버 동기화만 중단됩니다.

## 기술 스택

- React 19 + TypeScript
- Vite 8
- Node.js 내장 `http` 모듈 기반 동기화 API 서버(외부 서버 프레임워크 없음)
- JSON 파일 저장소(`DATA_DIR/store.json`), `scrypt` 비밀번호 해시, httpOnly 세션 쿠키
- 외부 UI/아이콘 라이브러리 없이 인라인 SVG와 직접 작성한 CSS 사용
- 상태 관리 라이브러리 없이 React 훅과 `localStorage` 사용
- `node:test` 기반 서버·검증·동기화 로직 테스트

## 시작하기

Node.js 20.19+ 또는 22.12+ 환경을 권장합니다. 동기화 서버는 Node.js 24에서 검증했습니다.

```bash
npm install
```

#### 로컬 전용으로 실행

```bash
npm run dev
```

개발 서버가 출력하는 주소(기본 `http://localhost:5173`)를 브라우저에서 엽니다. 이 모드에서는 기존처럼 `localStorage`만 사용합니다.

#### 동기화 서버와 함께 실행

터미널 두 개를 사용합니다.

```bash
# 터미널 1: API 서버(기본 http://127.0.0.1:8787)
npm run dev:server
```

```bash
# 터미널 2: Vite 개발 서버
npm run dev
```

Vite는 `/api` 요청을 `API_PROXY_TARGET`(기본 `http://127.0.0.1:8787`)으로 프록시합니다. 설정을 바꾸려면 `.env.example`을 `.env`로 복사한 뒤 수정하세요. `.env`는 서버와 Vite 설정에서 함께 읽습니다.

```bash
cp .env.example .env
```

### 빌드 및 배포

```bash
npm run build
npm start
```

- `npm run build`: 타입 검사(`tsc -b`) 후 프로덕션 빌드를 `dist/`에 생성합니다.
- `npm start`: API 서버를 실행하고 `dist/`의 정적 파일도 함께 제공합니다. 기본 주소는 `http://127.0.0.1:8787`입니다.
- `npm run typecheck`: 타입 검사만 실행합니다.
- `npm run preview`: 빌드 결과를 Vite 프리뷰 서버에서 확인합니다. 동기화까지 확인하려면 `npm start`를 사용하세요.
- `npm test`: 서버, 검증, 동기화, 북마크 가져오기 로직 테스트를 실행합니다.

## 사용 방법

| 동작 | 방법 |
| --- | --- |
| 검색 | 검색어 입력 후 `Enter` |
| 검색창 포커스 | `Ctrl+K` / `Cmd+K` |
| 검색어 지우기 | 검색창의 X 버튼 또는 `Esc` |
| 즐겨찾기 열기 | 카드 클릭 또는 카드에 포커스 후 `Enter` (새 탭) |
| 카드 메뉴 | 카드 우측 상단 `⋯` 버튼 |
| 카드 수정/삭제 | 카드 메뉴 → `수정` / `삭제` |
| 카테고리 이동 | 카드 메뉴 → `카테고리 이동` 또는 수정 모달의 카테고리 선택 |
| 카테고리 필터 | 즐겨찾기 영역 상단의 카테고리 탭 |
| 카테고리 관리 | 카테고리 탭 오른쪽 `관리` |
| 카테고리 순서 변경 | `관리` → 각 카테고리의 위/아래 버튼 |
| 순서 변경 | 카드 드래그 또는 카드 메뉴의 좌/우 이동 |
| 순서 변경 모드 | 하단 `순서 변경` |
| 필터 | 즐겨찾기 영역의 필터 입력창 |
| 설정 | 우측 상단 톱니바퀴 또는 하단 `테마 설정` |
| 데이터 백업 | 설정 → `데이터` |
| Chrome 북마크 가져오기 | 설정 → `데이터` → `북마크 HTML 선택` |
| 계정 로그인/동기화 | 설정 → `데이터` → `계정 및 동기화` |
| 모달/메뉴 닫기 | `Esc` 또는 배경 클릭 |

모바일·태블릿에서는 HTML5 드래그 앤 드롭이 안정적이지 않을 수 있으므로 카드 메뉴의 `왼쪽으로 이동`/`오른쪽으로 이동`을 사용하세요.

## 데이터 저장

| 키 | 내용 |
| --- | --- |
| `my-start-page.favorites.v1` | 즐겨찾기 배열 |
| `my-start-page.categories.v1` | 카테고리 배열(배열 순서가 탭 표시 순서) |
| `my-start-page.settings.v1` | 테마, 검색 엔진, 배경, 검색 결과 새 탭 설정 |
| `my-start-page.sync.v1` | 마지막 동기화 지문(fingerprint), 서버 버전, 동기화 시각 |
| `my-start-page.sync-session.v1` | 세션 복원 힌트(`1`). 세션 쿠키 자체는 httpOnly라 JS에서 읽지 않습니다. |

즐겨찾기 항목 형식:

```json
{
  "id": "unique-id",
  "name": "GitHub",
  "url": "https://github.com/",
  "iconUrl": "https://example.com/icon.png",
  "categoryId": "dev",
  "createdAt": 1700000000000
}
```

`iconUrl`은 선택 사항입니다. `categoryId`는 카테고리 배열에 존재하는 ID여야 합니다.

카테고리 항목 형식:

```json
[
  { "id": "dev", "name": "개발" },
  { "id": "ai", "name": "AI" },
  { "id": "etc", "name": "기타" }
]
```

카테고리 순서는 배열 순서를 그대로 사용합니다.

### 백업 파일 형식

```json
{
  "app": "my-start-page",
  "version": 2,
  "exportedAt": "2026-10-24T13:23:30.605Z",
  "favorites": [
    {
      "id": "starter-1",
      "name": "Google",
      "url": "https://www.google.com/",
      "categoryId": "etc",
      "createdAt": 1700000000000
    }
  ],
  "categories": [
    { "id": "dev", "name": "개발" },
    { "id": "ai", "name": "AI" },
    { "id": "work", "name": "업무" },
    { "id": "news", "name": "뉴스" },
    { "id": "shopping", "name": "쇼핑" },
    { "id": "etc", "name": "기타" }
  ],
  "settings": {
    "theme": "light",
    "searchEngine": "google",
    "background": { "type": "default" },
    "openInNewTab": false
  }
}
```

가져오기는 위 형식의 객체뿐 아니라 즐겨찾기 배열만 있는 JSON도 허용합니다. 배열만 가져오면 기존 카테고리와 설정은 유지됩니다. 버전 1 백업처럼 `categories`가 없는 객체도 가져올 수 있으며, 이때도 기존 카테고리는 유지됩니다. 최대 300개 즐겨찾기, 30개 카테고리, 5MB까지 가져올 수 있습니다.

## 동기화 서버

동기화는 선택 기능입니다. 서버를 실행하지 않아도 앱은 기존과 동일하게 `localStorage` 기반으로 동작합니다.

### 동작 방식

- 프론트엔드는 로컬 우선(local-first)입니다. 모든 변경은 먼저 `localStorage`에 저장됩니다.
- 로그인하면 `GET /api/sync`로 서버 스냅샷을 확인하고, 로컬 데이터의 지문(fingerprint)과 서버 지문, 마지막 동기화 지문을 비교합니다.
- 서버에 데이터가 없으면 현재 로컬 데이터를 첫 버전으로 업로드합니다.
- 로컬만 변경되면 `PUT /api/sync`로 올리고, 서버만 변경되면 내려받습니다.
- 양쪽이 모두 변경되면 자동으로 덮어쓰지 않고 충돌 카드를 표시합니다.
- 로컬 변경 후 1.2초 디바운스로 자동 동기화하며, `online` 이벤트가 발생하면 다시 시도합니다.
- `baseVersion`이 서버 버전과 다르면 `409 Conflict`와 현재 서버 스냅샷을 반환합니다. 클라이언트는 이 스냅샷으로 충돌 카드를 갱신합니다.
- 세션 쿠키는 httpOnly라 JavaScript에서 읽을 수 없습니다. 프론트엔드는 `my-start-page.sync-session.v1` 힌트로 새로고침 후 세션 복원을 시도합니다.

### API

| 메서드 | 경로 | 인증 | 설명 |
| --- | --- | --- | --- |
| `GET` | `/api/health` | 불필요 | 서버 상태 확인 |
| `POST` | `/api/auth/register` | 불필요 | 이메일·비밀번호 회원가입, 세션 쿠키 발급 |
| `POST` | `/api/auth/login` | 불필요 | 로그인, 세션 쿠키 발급 |
| `POST` | `/api/auth/logout` | 쿠키 | 세션 삭제 및 쿠키 만료 |
| `GET` | `/api/auth/me` | 필요 | 현재 사용자와 동기화 버전 요약 |
| `GET` | `/api/sync` | 필요 | 서버 동기화 스냅샷 조회 |
| `PUT` | `/api/sync` | 필요 | `baseVersion` 기반으로 즐겨찾기·카테고리·설정 저장 |

`PUT /api/sync` 요청 예시:

```json
{
  "baseVersion": 3,
  "favorites": [],
  "categories": [{ "id": "etc", "name": "기타" }],
  "settings": {
    "theme": "light",
    "searchEngine": "google",
    "background": { "type": "default" },
    "openInNewTab": false
  }
}
```

성공 시 `200`과 `{ "version": 4, "updatedAt": "...", "data": { ... } }`를 반환합니다. 버전이 오래되면 `409`와 `{ "error": "...", "current": { ... } }`를 반환합니다.

### 마이그레이션

1. 기존 로컬 데이터는 그대로 유지됩니다. 서버를 켜고 설정 → `데이터` → `계정 및 동기화`에서 로그인하거나 회원가입합니다.
2. 서버에 해당 계정의 데이터가 없으면 현재 로컬 데이터가 첫 버전으로 업로드됩니다.
3. 다른 기기에서 같은 계정으로 로그인하면 서버 데이터를 내려받습니다.
4. 서버와 로컬이 모두 변경된 상태라면 충돌 카드에서 사용할 데이터를 선택합니다. 선택 전까지 자동 덮어쓰기는 발생하지 않습니다.
5. JSON 백업/복원은 동기화와 별개로 계속 사용할 수 있습니다. 대규모 정리나 초기화 전에는 JSON 백업을 권장합니다.

### 보안 및 운영 참고

- 비밀번호는 `scrypt`로 해시하고 salt를 사용자별로 저장합니다. 비교는 `timingSafeEqual`을 사용합니다.
- 세션 토큰은 httpOnly, `SameSite=Lax` 쿠키로 전달하며, 서버에는 토큰 원문 대신 SHA-256 해시만 저장합니다.
- API 입력은 URL(http/https), 카테고리 ID/이름, 최대 개수, 설정 enum, 본문 크기를 검증합니다.
- 응답에는 `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`를 설정합니다.
- HTTPS 배포 시 `COOKIE_SECURE=true`를 설정하고, 리버스 프록시 뒤에서 `HOST`/`PORT`를 조정하세요.
- 현재 서버는 단일 프로세스 JSON 파일 저장소입니다. 여러 인스턴스로 수평 확장하려면 공유 데이터베이스와 분산 잠금이 필요합니다.
- 이메일 인증, 비밀번호 재설정, 로그인 시도 제한(rate limit), 감사 로그는 포함되어 있지 않습니다. 공개 인터넷에 배포할 때는 리버스 프록시나 별도 인증 계층에서 보완하세요.
- 서버 저장 데이터는 파일 시스템 권한으로 보호됩니다. 운영체제 수준의 디스크 암호화와 백업 정책을 함께 사용하세요.

## 제한 사항

- **최근 방문 기록은 제공하지 않습니다.** 일반 웹 페이지는 브라우저 방문 기록에 접근할 수 없기 때문에 실제 기록을 수집할 수 없습니다. 필요하다면 브라우저 확장 프로그램이나 별도 동의 기반 수집이 필요합니다.
- 즐겨찾기 아이콘과 이미지 배경은 외부 네트워크에 의존합니다. 오프라인이거나 favicon 요청이 차단되면 글자 아바타로 대체됩니다.
- 기본 favicon 조회는 Google S2 서비스를 사용하므로 사이트 도메인이 Google로 전송됩니다. 민감한 환경에서는 사용자 지정 아이콘 URL을 사용하세요.
- 데이터는 기본적으로 현재 브라우저 프로필의 `localStorage`에 저장됩니다. 계정 동기화를 사용하지 않으면 기기 간 자동 동기화나 자동 백업은 없으며, 브라우저 데이터를 지우면 함께 삭제됩니다.
- 서버 동기화는 로그인 후 수동/자동으로 동작하며 실시간 협업 편집은 지원하지 않습니다. 동시에 여러 기기에서 편집하면 충돌 카드에서 선택해야 합니다.
- 서버 저장소는 단일 프로세스용 JSON 파일입니다. 대규모 사용자나 다중 서버 배포에는 적합하지 않습니다.
- 이미지 배경은 외부 URL만 지원합니다. 로컬 파일 업로드는 지원하지 않습니다(외부 URL은 적용 전에 로드 여부를 확인합니다).
- 모바일에서의 카드 드래그 정렬은 브라우저별 편차가 있어 메뉴 이동 버튼을 권장합니다.
- 카테고리는 최대 30개, 이름은 최대 20자까지 지원합니다. 카테고리는 최소 1개가 필요합니다.
- 선택한 카테고리 탭은 새로고침하면 `전체`로 돌아갑니다. 카테고리 자체와 순서는 저장됩니다.
- 즐겨찾기는 최대 300개까지 가져올 수 있고, 백업 파일은 5MB로 제한됩니다.
- 검색 기록과 방문 통계는 제공하지 않습니다. 계정 기반 동기화는 즐겨찾기·카테고리·설정만 대상으로 합니다.
